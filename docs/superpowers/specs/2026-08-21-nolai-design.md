## 1. 서비스 정의

만 10~13세(초등 3~6학년) 한국 어린이가 AI의 작동 원리를 **글로 읽지 않고 손으로 만져서** 이해하는 온라인 놀이터.

기존 어린이 코딩 교육(스크래치, 엔트리, code.org)은 프로그래밍 기초를 다룬다. 놀AI는 그 시장에 들어가지 않는다. 대신 **"AI가 어떻게 생각하는가"**를 다룬다 — 임베딩, 벡터검색, RAG 같은 개념을 아이 눈높이에서 시각화하고 직접 조작하게 한다. 이 영역은 어른용 자료조차 대부분 글과 도표뿐이며, 어린이용은 사실상 비어 있다.

### 시장과 경쟁 (2026-08-21 조사)

**어린이 AI 교육 도구는 거의 전부 "분류" 한 개념에 몰려 있다.**

| 서비스 | 다루는 개념 |
|---|---|
| Teachable Machine (Google) | 학습 데이터 → 분류 |
| Machine Learning for Kids (IBM 기반) | 텍스트·이미지 분류 |
| AI for Oceans (Code.org) | 분류 + 편향 |
| 엔트리 AI 블록 (네이버 커넥트재단) | 이미지·텍스트·음성 모델 학습 |

셋 다 훌륭하지만 가르치는 것은 같다 — *"예시를 많이 주면 컴퓨터가 구분한다."* 여기 몰린 이유는 **시각화가 쉬워서다.** 물고기와 쓰레기를 나누는 것은 눈에 바로 보인다.

국내 사교육(AI EDUTOM, 에이아이런, AI KIDS LAB, ABCDEdu 등)은 방향이 다르다. 대부분 **생성 AI 활용법이나 오프라인 캠프**이며 원리 시각화가 아니다.

임베딩·벡터 시각화 도구는 많지만 **전부 개발자·성인 대상**이다. 어린이용은 AAAI에 발표된 K-12 워드 임베딩 시각화 연구 정도로, 학술 프로토타입이지 서비스가 아니다.

```
분류 · 학습데이터   ████████████████  포화
AI 활용법(ChatGPT)  ████████████      포화
임베딩 · 벡터검색    ▓                 어른용만 존재
RAG · 환각           ░                 사실상 없음
```

**놀AI가 노리는 자리는 어린이 대상으로 비어 있다.** 다만 비어 있는 이유를 정직하게 인식해야 한다 — **어렵기 때문이다.** 분류는 사진으로 보여주면 끝이지만 임베딩은 "말을 숫자로 바꾼다"는 추상 개념이라 시각화 난이도가 훨씬 높다. 이 서비스의 가치와 리스크가 정확히 같은 지점에 있다.

**순풍:** 2026년부터 2022 개정교육과정에서 초등 실과에 "데이터와 인공지능"이 정규 편입된다. 학부모 수요가 구조적으로 증가하는 시점이다. 성취기준 단위의 매핑은 15장에 있다.

**리스크:**

1. **엔트리가 임베딩 블록을 추가할 수 있다.** 다만 엔트리는 "블록으로 만들기" 플랫폼이고 놀AI는 "개념 놀이터"라 결이 다르다. 정면 충돌은 아니다
2. **경쟁자가 전부 무료다.** 유료화 경로가 보이지 않는다. 지금 단계의 문제는 아니지만 언젠가 마주한다
3. **학교 채택은 어렵다.** 교과서·인증 연계가 필요하다. **B2C(집에서 혼자 하는 아이)를 전제로 설계한다**

**포지셔닝: "엔트리 다음에 오는 곳".** 엔트리에서 이미지 분류를 해본 아이가 *"근데 컴퓨터가 어떻게 아는 거지?"*라고 물었을 때 갈 곳이 지금은 없다. 어른용 유튜브 영상뿐이다. 엔트리와 경쟁하지 않고 **그 위층에 선다.**

참고: [엔트리](https://playentry.org/) · [엔트리 초등 AI교육 평가(AI타임스)](https://www.aitimes.com/news/articleView.html?idxno=133294) · [2022 개정교육과정 실과 데이터·인공지능](https://dandi.pen.go.kr/courses/course-v1:DANDI+GBE3104x+2025_Y104/about) · [AI for Oceans](https://code.org/oceans) · [K-12 워드 임베딩 시각화 연구(AAAI)](https://ojs.aaai.org/index.php/AAAI/article/view/21548)

### 타겟

**만 10~13세, 단일 페르소나.**

"초등학생 전체"로 넓히지 않는다. 저학년(7~9세)과 고학년(10~13세)은 읽기 능력, 입력 방식(타이핑 가능 여부), 추상 개념 수용도, 사용 상황(보호자 동반 여부)이 모두 달라 사실상 다른 사용자다. 둘을 모두 만족시키려면 콘텐츠를 두 벌 만들어야 한다.

10~13세로 정한 이유는 두 가지다. **혼자 들어와서 놀 수 있는 최저 나이**이면서, 임베딩·벡터검색을 은유로 얼버무리지 않고 진짜로 이해시킬 수 있는 최저 나이다.

저학년용 쉬운 모드는 만들지 않는다. 나중에 필요해지면 그때 붙인다.

## 2. 핵심 설계 원칙

모든 레슨과 화면이 지켜야 할 네 가지.

1. **설명보다 조작이 먼저 온다.** 부엉이의 말은 지시가 아니라 아이 행동에 대한 반응이어야 한다.
2. **틀린 답이 없다.** 아이가 무엇을 하든 놀이터는 반응하고, 왜 그렇게 되는지만 보여준다. 실패 상태를 만들지 않는다.
3. **한 레슨은 10분.** 이 나이대 집중력의 현실적 상한.
4. **모든 숫자는 진짜다.** 임베딩 좌표는 실제 모델로 미리 계산한 값이다. 아이가 나중에 커서 확인해도 거짓말이 아니어야 한다.

## 3. 사용자 여정

### 첫 방문 — 60초 안에 놀이터까지

```
랜딩 ─→ 이름 정하기 ─→ 비밀코드 발급 ─→ 첫 레슨 놀이터
        (랜덤 추천      (크게 표시,      (설명 없이
         3개 중 선택)    "적어둬!")       바로 조작)
```

가입 화면의 입력란은 **닉네임 하나**다. 기본 동작은 랜덤 추천 3개 중 클릭해서 고르는 것이고, 직접 입력은 옵션이다. 이 방식이 실명 입력을 구조적으로 막으면서 동시에 가입 마찰을 없앤다.

랜딩 페이지는 부모·교사가 검색으로 도착하는 입구이기도 하다. **SEO 대상은 랜딩 페이지뿐**이다.

### 재방문

```
같은 기기  ─→ (자동 입장) ─→ 내 방
다른 기기  ─→ 닉네임+코드 ─→ 내 방
                               ├─ 진도 지도   (어디까지 왔나)
                               ├─ 배지 선반   (모은 것)
                               └─ 내 작품     (놀이터에서 만든 결과물)
```

"내 방"은 재방문의 유일한 이유다. 놀이터만 있으면 데모이지 서비스가 아니다. 따라서 첫 버전에 반드시 포함한다.

**같은 기기에서는 비밀코드를 다시 입력하지 않는다.** 서명된 세션 쿠키(만료 1년)를 발급하므로, 코드는 기기를 바꿀 때만 필요하다. 매 방문마다 코드를 요구하면 이탈한다.

## 4. 계정 — 닉네임 + 비밀코드

### 왜 정식 회원가입을 하지 않는가

타겟 연령이 10~13세이므로 **전원이 만 14세 미만**이다. 한국 개인정보보호법상 만 14세 미만의 개인정보를 수집하려면 법정대리인 동의 절차가 필수다. 이메일 회원가입 하나를 넣는 순간 부모 동의 확인 플로우, 동의 기록 보관, 아동용 개인정보처리방침이 모두 따라온다.

더 현실적인 문제는 이탈이다. 아이는 부모를 부르러 가다가 그냥 나간다.

닉네임과 비밀코드는 개인정보가 아니므로 동의 절차 대상이 아니다. 그러면서 아이 입장에서는 **"내 계정"이 맞다** — 진도, 배지, 작품이 서버에 쌓이고 기기를 바꿔도 유지된다. 비밀코드를 받는 경험 자체가 게임 같아서 오히려 선호된다.

정식 회원가입(부모 동의 포함)은 사용자가 늘면 그때 도입한다.

### 사양

**닉네임**
- 기본: 랜덤 단어 조합 3개를 제시하고 클릭해서 선택 (`번개토끼`, `무지개상어`, `초코로봇`)
- 직접 입력은 옵션. 실명 패턴과 금칙어를 필터링한다
- **중복 허용**. 로그인은 닉네임과 코드의 조합으로 이루어지므로 닉네임 자체는 유일할 필요가 없다

**비밀코드**
- 6자리, 문자셋은 `23456789ABCDEFGHJKMNPQRSTUVWXYZ` (31자)
- 혼동 문자 `0 O 1 I L`을 제외한다. 아이가 종이에 적었다가 못 알아보면 계정을 잃는다
- 저장은 해시(bcrypt). 닉네임으로 후보를 조회한 뒤 코드를 검증한다

**로그인**
- 닉네임과 비밀코드가 **둘 다** 일치해야 한다. 코드만으로 로그인하면 아무 코드나 찍어서 남의 방에 들어갈 수 있다
- IP당 분당 5회 시도 제한

**코드 분실**
- 개인정보를 받지 않으므로 **복구 수단이 없다.** 이것은 설계상 감수하는 비용이다
- 완화책: 발급 화면에서 코드를 크게 표시하고 "이미지로 저장" 버튼을 제공한다. 발급 시점에 분실하면 복구할 수 없음을 명확히 경고한다
- 실무적으로는 세션 쿠키가 1년간 유지되므로, 같은 기기를 쓰는 한 코드를 쓸 일이 없다

## 5. 레슨 구조

### 뼈대 — 만져보기가 먼저, 이름은 나중에

모든 레슨은 다음 5단계를 따른다.

| 단계 | 하는 일 |
|---|---|
| **hook** | 부엉이가 질문을 던진다. 답은 주지 않는다 |
| **play** | 설명 없이 놀이터를 조작한다. 부엉이는 반응만 한다 |
| **name** | "방금 한 게 임베딩이야"라고 이름을 붙인다 |
| **challenge** | 배운 것으로 문제를 푼다 |
| **reward** | 배지를 받고 작품이 내 방에 저장된다 |

추상 개념은 설명을 먼저 들으면 튕겨 나간다. 손으로 먼저 겪은 뒤에 설명이 붙는다.

### 저장 형태 — 겁데기는 데이터, 놀이터는 코드

레슨의 **놀이터 부분은 개념마다 인터랙션이 완전히 다르다.** 임베딩은 지도 위에서 점을 끌어다 놓는 것이고, 벡터검색은 거리를 재는 것이다. 이를 "설정으로 조립 가능한 범용 위젯"으로 일반화하려는 시도는 어느 개념에도 맞지 않는 결과를 낳는다.

반대로 놀이터를 뺀 나머지(부엉이 대사, 개념 설명, 도전 문제, 배지)는 개념이 달라도 형태가 같다.

따라서 **레슨 1개 = JSON 파일 1개 + 놀이터 컴포넌트 이름 하나**로 저장한다.

```json
{
  "id": "embedding-map",
  "order": 1,
  "lang": "ko",
  "title": "비슷한 말끼리 모여라",
  "playground": "EmbeddingMap",
  "dataset": "words-animals-vehicles",

  "steps": [
    { "type": "hook",
      "owl": "컴퓨터는 '강아지'라는 말을 몰라. 그럼 어떻게 알아듣지?" },

    { "type": "play",
      "owl": ["아무거나 끌어다 놔봐!",
              "어? 강아지랑 고양이가 붙었네. 왜 그럴까?",
              "자동차도 한번 놔볼래?"],
      "goal": { "minPlaced": 5 } },

    { "type": "name",
      "concept": "임베딩",
      "body": "컴퓨터는 말을 숫자로 바꿔서 기억해. 비슷한 뜻일수록 숫자가 비슷해지고, 그래서 지도에서 가까이 붙는 거야." },

    { "type": "challenge",
      "question": "'호랑이'는 어디에 놓일까?",
      "choices": ["강아지 근처", "자동차 근처", "사과 근처"],
      "answer": 0,
      "explain": "호랑이도 동물이니까 강아지·고양이 쪽으로 가!" },

    { "type": "reward", "badge": "map-explorer" }
  ]
}
```

문구 수정, 난이도 조정, 도전 문제 추가는 이 파일만 고치면 된다. 코드를 열지 않는다.

레슨 JSON은 zod 스키마로 검증하며, CI에서 전체 레슨 파일을 검사한다.

### 놀이터 컴포넌트 계약

**놀이터는 레슨 흐름을 모른다.** 이것이 핵심 설계 결정이다.

```ts
interface PlaygroundProps {
  data: PlaygroundDataset                   // 미리 계산된 진짜 임베딩 좌표
  onEvent: (e: PlaygroundEvent) => void     // "아이가 방금 이걸 했어요"
  onArtifact: (a: Artifact) => void         // "이걸 만들었어요" → 내 방에 저장
}
```

`EmbeddingMap`은 점을 그리고 끄는 것만 안다. 부엉이가 언제 무슨 말을 하는지, 다음 단계가 무엇인지는 바깥의 `LessonRunner`가 `onEvent`를 받아 판단한다.

이렇게 분리해야 (1) 새 개념을 추가할 때 놀이터 하나만 쓰면 되고, (2) 놀이터를 단독으로 열어 테스트할 수 있다. 놀이터 안에 부엉이 대사를 박아 넣으면 레슨마다 놀이터를 복사하게 된다.

## 6. 실습 방식 — 미리 계산된 진짜 데이터

실행 중 LLM이나 임베딩 API를 **호출하지 않는다.**

임베딩은 사전에 실제 모델로 계산해 정적 데이터로 저장한다. 아이는 진짜 AI가 만든 숫자를 만지지만, 서비스는 API를 한 번도 부르지 않는다.

이 선택으로 세 가지가 동시에 해결된다.

- **비용 0** — 사용자가 늘어도 추론 비용이 없다
- **유해 콘텐츠 위험 0** — 아동 대상 서비스에서 LLM 자유 입력은 필터링과 어뷰징 방지 설계를 반드시 요구한다. 아예 없앤다
- **속도** — 네트워크 왕복 없이 즉시 반응한다

**이로 인한 제약을 명시한다.** 아이가 임의의 문장을 자유 입력할 수 없다. 질문과 단어는 **미리 준비된 카드 중에서 고른다.** 카드를 충분히 많이(20개 이상) 두어 자유도를 체감하게 한다.

## 7. 첫 버전 범위

### 뼈대 (콘텐츠와 무관)

- **온보딩** — 닉네임 고르기 → 비밀코드 발급
- **내 방** — 진도 지도 · 배지 선반 · 내 작품
- **레슨 러너** — JSON을 읽어 5단계를 진행
- **DB** — kids / progress / artifacts / badges
- **랜딩 페이지** — SEO 대상

### 레슨 2개

**레슨 1 — 비슷한 말끼리 모여라 (임베딩)**

- 놀이터: `EmbeddingMap`
- 데이터: 단어 20개 내외 (동물 / 탈것 / 음식 3개 카테고리) + 실제 임베딩을 2D로 투영한 좌표
- 조작: 단어 카드를 지도 아무 곳에나 끌어다 놓으면, 자석에 끌리듯 **진짜 자리로 스프링 애니메이션하며 이동**한다. 가까운 단어끼리는 사이에 선이 생기고, 가까울수록 굵어진다
- **클릭으로도 배치할 수 있다.** 드래그가 주된 조작이지만, 터치만 쓰는 아이나 소근육 조작이 어려운 아이를 위해 카드를 누르기만 해도 배치되는 경로를 항상 함께 제공한다
- 아하: *내가 아무 데나 놔도 컴퓨터가 아는 자리로 간다. 비슷한 것끼리 모인다.*
- 이 방식은 "틀린 답이 없다" 원칙을 지킨다. 아이는 실패하지 않고, 컴퓨터가 이미 답을 알고 있다는 것만 보게 된다
- 배지: `map-explorer` (표시명 "지도 탐험가")

**레슨 2 — 가장 가까운 걸 찾아줘 (벡터검색)**

- 놀이터: `NearestSearch`
- 데이터: 짧은 문장 조각 30개 내외(동물 백과사전 형식) + 질문 카드 20장 + 미리 계산된 유사도
- 조작: 질문 카드를 고르면 지도에 질문이 한 점으로 나타나고, 가까운 문장 3개로 빛이 뻗어나가며 순위가 매겨진다
- 아하: *검색은 "똑같은 단어"를 찾는 게 아니라 "뜻이 가까운 것"을 찾는 거구나.*
- 배지: `path-finder` (표시명 "길 찾기 대장")

배지는 `badges` 테이블에 영문 id로 저장하고, 표시명과 아이콘은 프론트엔드 배지 정의 파일에서 관리한다.

두 레슨은 이어져서 하나의 이야기를 만든다 — 말을 지도 위 위치로 바꾸고(1), 그 지도에서 가장 가까운 것을 찾는다(2). 레슨 2 끝에서 아이가 직접 검색을 성공시키는 순간이 첫 버전의 절정이다.

### 첫 버전에 넣지 않는 것

- 실제 LLM API 호출
- 토큰 · RAG · 환각 레슨 (2차)
- 부모 · 교사 대시보드
- 결제 및 유료화
- 저학년(7~9세) 모드
- 모바일 앱, 다국어

## 9. 아트 디렉션

### 톤 — 팝 캔디, 전체 밝은 톤

두꺼운 검은 외곽선(`#1F2430`), 고채도 색, 아래로 떨어지는 입체 그림자. 요즘 게임 UI의 정석이며 조작 유도가 가장 강하다. 아이가 설명 없이 먼저 만져야 하는 구조에서 "이거 눌러도 돼"라는 신호가 명확해야 한다.

파스텔 톤은 채택하지 않는다. 10~13세는 유아용으로 보이는 것에 민감하다.

### 화려함을 어디에 쓰는가

화려함을 화면 전체에 균일하게 뿌리지 않는다. 놀이터 안에서 아이가 읽어야 하는 정보는 점들 사이의 **거리**인데, 배경이 번쩍이면 그것이 보이지 않는다.

| 구역 | 연출 |
|---|---|
| 홈 · 내 방 · 배지 획득 · 레슨 시작/완료 | 최대한 화려하게 — 파티클, 효과음, 캐릭터 애니메이션 |
| 놀이터 안쪽 | 배경은 절제, 대신 **반응**을 화려하게 |

놀이터에서 화려함은 배경 장식이 아니라 *"내가 점을 놓으면 스프링처럼 튕기며 자리를 찾아가는 것"*으로 쓴다. 더 재미있고 개념도 더 잘 보인다.

### 색 규칙

밝은 배경에서는 거리가 색에 묻힐 수 있다. 다음 규칙으로 해결한다.

- **거리는 색이 아니라 선으로 표현한다.** 두 단어가 가까우면 사이에 선이 생기고, 가까울수록 굵어진다
- **색은 카테고리에만 쓰고 3색으로 제한한다** (동물 / 탈것 / 음식)
- 놀이터 지도 영역은 UI 배경과 다른 밝기 + 두꺼운 외곽선으로 명확히 구분한다

### 효과음

첫 버전에 포함한다. 아이 대상 서비스에서 효과음 유무는 체감 완성도를 크게 가른다. 단, 음소거 버튼을 눈에 띄는 곳에 둔다(교실·도서관 사용 대비).

## 10. 기술 스택

**Next.js (App Router) + Supabase + Vercel**

- 서버 로직은 Route Handler로 충분하다. 별도 API 서버를 두면 관리 대상만 늘고 얻는 것이 없다
- Vercel 무료 + Supabase 무료 티어로 유지비가 사실상 0
- 랜딩 페이지 SEO가 필요하므로 SSR이 되는 편이 낫다

### 폴더 구조

```
nolai/
├── frontend/              # Next.js — 사실상 전부
│   ├── app/               # 라우트
│   ├── lessons/           # 레슨 JSON
│   ├── playgrounds/       # 놀이터 컴포넌트
│   ├── copy/              # UI 고정 문자열
│   └── datasets/          # 미리 계산된 임베딩 좌표
├── database/              # Supabase 마이그레이션
├── tools/embed/           # 파이썬(uv) — 임베딩 사전 계산
├── docs/
└── CLAUDE.md
```

`backend/`가 없는 것은 의도적이다. CLAUDE.md의 표준 풀스택 구조에서 벗어나지만, Supabase와 Route Handler가 서버 역할을 모두 수행하므로 빈 껍데기 서버를 두지 않는다.

`tools/embed/`만 파이썬이며 uv로 관리한다. 배포와 무관하게 로컬에서 가끔 실행하는 도구다.

`frontend/copy/`에는 UI 고정 문자열("다 했어요", "내 방", "배지를 받았어!" 등)을 모은다. 다국어 대비가 아니라 **문구 톤을 한곳에서 관리하기 위해서다.** 아이 대상 서비스는 말투 일관성이 완성도를 좌우하는데, 컴포넌트마다 문자열이 흩어지면 관리가 불가능해진다.

### 임베딩 사전 계산 파이프라인

`tools/embed/`가 하는 일:

1. 단어·문장 목록(YAML)을 읽는다
2. 임베딩 모델로 벡터를 계산한다
3. 2D로 투영한다
4. `frontend/datasets/*.json`으로 출력한다

출력물은 git에 커밋한다. 빌드 시점에 재계산하지 않는다 — 좌표가 바뀌면 레슨의 도전 문제 정답이 흔들리기 때문이다.

## 11. 에러 처리

|---|---|
| 비밀코드 분실 | 복구 불가. 발급 시점에 명확히 경고하고 이미지 저장 버튼 제공. 세션 쿠키 1년으로 실질 발생률을 낮춤 |

| 로그인 무차별 시도 | IP당 분당 5회 제한. 초과 시 대기 안내 |

## 13. 확장 로드맵

이 설계가 어떤 확장을 싸게 받아주고 어떤 확장을 비싸게 받는지 미리 구분해 둔다. 확장성이란 모든 것에 대비하는 것이 아니라, **무엇이 싸고 무엇이 비싼지 아는 것**이다.

### A. 그릇이 이미 받아주는 것 — 뼈대 수정 0

- **새로운 AI 개념 레슨** — 놀이터 컴포넌트 1개 + JSON 1개면 끝난다. 토큰, 환각, 학습 데이터, 편향, 프롬프트, 이미지 생성 원리, 신경망, 분류 등이 모두 여기 해당한다. 이것이 겁데기와 놀이터를 분리한 이유다. **단서**: 기존 데이터셋 형태를 재사용할 때만 그렇다. 레슨 2는 데이터 형태 자체가 달라 뼈대 네 곳을 먼저 일반화해야 했다 (14장 2026-08-22 항목 참고)
- 배지 · 작품 종류 추가
- 레슨 순서 재구성

첫 버전을 레슨 2개로 줄인 비용이 크지 않은 이유가 여기 있다. **3번째 레슨부터는 훨씬 빠르다.**

### B. 손이 가지만 되는 것

| 확장 | 필요한 작업 |
|---|---|
| 코딩 기본 개념(변수·반복문) 레슨 | 기술적 장벽 없음. "AI 특화" 포지셔닝이 흐려지는 **전략 문제**일 뿐 |
| 저학년(7~9세) 모드 | 구조는 받아준다. 다만 **콘텐츠를 두 벌** 써야 한다 |
| 부모 · 교사 대시보드 | `progress` 테이블이 이미 있어 읽기는 쉽다. "아이 ↔ 보호자 연결" 테이블 추가 필요 |
| 커리큘럼 트랙 | 지금은 `order` 하나로 일렬이다. 개념이 20개를 넘으면 JSON에 `track` 필드 추가 |
| 정식 회원가입 · 결제 | `kids` 테이블 확장 + 만 14세 미만 법정대리인 동의 절차 구축 |

### C. 전제를 바꿔야 하는 것

**실제 LLM 대화 / 아이 자유 텍스트 입력**

"실행 중 API 호출 없음"은 이 설계의 뼈대다. 이를 도입하려면 아동 유해 콘텐츠 필터링, 비용 통제, 어뷰징 방지가 통째로 필요하다. **아키텍처 문제가 아니라 운영 문제**이며, 사실상 다른 서비스가 된다. 의도적으로 닫아둔 문이다.

**다국어 — 지금 하지 않는다 (2026-08-21 판단)**

다국어 비용의 대부분은 i18n 배관이 아니다.

| 항목 | 비중 |
|---|---|
| 임베딩 데이터셋 재구축 (해당 언어로 재계산, 좌표 재검증) | 큼 |
| 부엉이 대사 · 개념 설명 번역 (직역 불가, 눈높이를 다시 잡아야 함) | 큼 |
| 도전 문제 정답 재검증 (좌표가 바뀌면 정답도 바뀜) | 중간 |
| i18n 배관 | 작음 |

미리 깔 수 있는 것은 맨 아래 한 줄뿐이고, 위 셋은 미리 할 수 없다. 배관을 지금 깔아도 큰 비용은 그대로 남는다.

반면 지금 깔면 손해가 실재한다. 레슨 문구를 다듬는 것이 이 서비스에서 가장 자주 하는 작업인데, 문자열이 `{"ko": ..., "en": ...}`이나 키 참조로 바뀌면 그 작업이 매번 번거로워진다.

레슨 JSON은 zod로 구조가 고정돼 있어 `"문자열"` → `{"ko": "문자열"}` 일괄 변환이 기계적이다. **레슨이 5개를 넘어갈 때 재판단한다.**

대신 비용이 0인 두 가지는 처음부터 적용한다.

- 레슨 JSON에 `lang` 필드 (필드 하나로 나중의 언어 구분이 공짜가 된다)
- UI 고정 문자열을 `frontend/copy/`에 모은다 (다국어 대비가 아니라 문구 톤 일관성을 위해)

## 14. 결정 기록

설계 당시 미뤄두었던 항목들을 구현 계획 작성 시점(2026-08-21)에 확정했다.

**임베딩 모델 — `nlpai-lab/KURE-v1` (로컬 실행)**

고려대가 BAAI/bge-m3를 한국어 검색용으로 파인튜닝한 모델이다. 한국어 검색 벤치마크에서 bge-m3 원본을 앞선다. 로컬 GPU에서 돌리므로 API 키가 필요 없고, 누구나 같은 결과를 재현할 수 있으며, 데이터셋을 늘릴 때 비용이 들지 않는다.

**2D 투영 — MDS (PCA·UMAP 아님)**

레슨의 핵심 정보가 점들 사이의 **거리**이므로, 거리 보존을 목적함수로 삼는 MDS가 맞다. PCA는 분산 최대화라 거리 보존을 보장하지 않고, UMAP은 표본이 50개 미만일 때 불안정하며 전역 거리를 지키지 않는다. `random_state=42`로 고정해 재현 가능하게 한다.

**마스코트 — 부엉이 "노리"**

순우리말 "놀이"에서 왔다. 서비스명 놀AI와 이어지고 두 글자라 부르기 쉽다.

**폰트 — Pretendard Variable (900 / 700 / 500)**

팝 캔디의 인상은 두꺼운 외곽선과 입체 그림자가 만든다. 폰트는 가독성을 우선하는 편이 맞고, CDN 한 줄로 끝나 리스크가 없다. 디스플레이용 개성 폰트는 필요해지면 나중에 교체한다.

**레슨 2의 배치 — 2D 지도가 아니라 질문 중심 방사 배치**

위 "2D 투영 — MDS" 항목은 레슨 1에는 맞았지만 레슨 2에는 맞지 않았다. 문장 30개와 질문 20개를 한 지도에 MDS로 올려 봤더니, **질문 20개 중 15개에서 원본 임베딩 1등이 화면상 7~29등**에 놓였다. 원인은 투영 알고리즘이 아니라 원본 공간이다 — 문장이 전부 "동물 사실"이라 유사도가 0.26~0.71의 좁은 띠에 몰려 있고(1등과 2등의 격차 평균 0.075, 최소 0.003), 2D로 누르면 그 미세한 차이가 먼저 사라진다.

"가장 가까운 걸 찾아줘"라는 레슨에서 **화면에서 가까워 보이지 않는 것을 정답이라고 말하게 되는 것**은 받아들일 수 없다. 그래서 거리를 투영에 맡기지 않는다. 질문을 화면 한가운데 고정하고, 문장은 자기 방향(MDS 각도 순서를 고르게 편 값)을 유지한 채 **실제 코사인 유사도를 반지름으로** 둘러선다. 화면 거리 = 진짜 유사도이므로 어긋남이 구조적으로 0이다. 1·2등이 동점인 질문에서 두 점이 나란히 붙어 서는 것도 거짓이 아니라 사실 그대로다.

정규화 기준은 데이터셋 전체에서 한 번 잰다(`simRange`). 질문마다 따로 정규화하면 어떤 질문에서든 1등이 중심에 딱 붙어 보여, 실제로는 답이 애매한 질문까지 확신에 차 보인다.

이건 실제로 일어나고, 검색·환각의 한계를 아이 눈높이로 짚는다. 착수 전에 다시

겹치지 않는다. 게다가 답이 없으면 **1·2등 격차가 0.002까지 좁혀진다** -- 문장들이
다 고만고만하게 안 맞는다는 뜻이고, 화면에서는 막대 셋이 나란히 짧게 보인다.
아이가 숫자를 몰라도 눈으로 알아챈다.

질문 두 개는 걸러냈다. "비행기는 어떻게 하늘에 떠?"는 펭귄 문장(하늘로는 오르지
못한다)과 실제로 관련이 있어 0.592가 나왔고, "공룡은 왜 다 사라졌어?"는 0.530으로
답이 있는 질문의 최소와 겹쳤다.

**놀이터를 새로 만들지 않았다.** NearestSearch에 "닮은 정도" 막대만 더했고, 그
막대는 레슨 2에도 도움이 된다(1·2등이 동점인 질문에서 막대가 나란한 것이 보인다).
13장 A가 말한 "놀이터 1개 + JSON 1개"보다도 싼 경우다 -- 놀이터 0개, JSON 1개,
데이터셋 1개.

**문구에서 지킨 선**: 이 레슨은 "AI를 믿지 마"가 아니라 **"AI는 자기가 모른다는
것을 모른다"**를 가르친다. 아이가 AI를 무서워하게 만드는 것은 목표가 아니다.

**레슨 3은 데이터셋을 새로 만들었다**

레슨 1의 18단어(`words.yaml`)로 분류를 시켜보니 병아리→딸기, 물고기→바나나,
포도→버스가 2D에서 가장 가까웠다. 레슨 1은 선 임계값이 이 잡음을 가려줬지만 레슨 3은
정면으로 드러낸다. 그래서 경계가 깨끗한 20단어를 새로 골랐다(`teach.yaml`). 각
카테고리를 눈에 띄게 다른 두 갈래로 나눈 것도 이때 정한 규칙이다.

**중심점이 아니라 가장 가까운 예시를 본다**

예시들의 평균점을 쓰면 예시를 더 줄수록 정확도가 **떨어지는** 구간이 생긴다(실제로
1개씩 가르쳤을 때 14/15, 2개씩일 때 9/12였다). "가르칠수록 잘한다"를 가르치려는
레슨에서 그건 거짓말이 된다. 가장 가까운 예시 하나를 보면 그 역전이 사라지고,
덤으로 아이에게 이유를 짚어줄 수 있다 -- 평균점은 화면에 없지만 예시는 화면에 있다.

**실패를 먼저 겪게 한다**

골고루 가르치면 컴퓨터가 20개 중 16개를 전부 맞힌다. 그러면 "안 보여준 건 모른다"는
아하가 화면에 나타나지 않는다. 그래서 부엉이가 **하나만 가르치고 물어보게** 유도한다.
전부 한 상자로 몰리는 장면을 먼저 겪은 뒤에 예시를 늘리는 순서다. 도전 문제도 그
장면을 묻는다 -- 겪지 않은 것을 물으면 2장의 "설명보다 조작이 먼저"를 어긴다.

**질문 문구는 추상적으로 에두르면 안 된다**

"낱말이 겹치지 않게 하라"는 규칙을 지키려다 질문을 두루뭉술하게 쓰면 엉뚱한 문장에 붙는다. "자라면서 생김새가 달라지는 동물은?"은 뱀의 허물에, "나중을 위해 남겨 두는 동물은?"은 낙타의 혹에 붙었다. 규칙의 뜻은 **다른 낱말로 같은 뜻**이지 두루뭉술하게 말하기가 아니다. 후보 문구를 여러 개 두고 실제 순위를 재서 고르는 편이 빠르다.

## 15. 교육과정 매핑

2026-08-22 확인. 1장의 "순풍"을 성취기준 단위로 따져본 결과다.

### 확인한 사실

2022 개정 교육과정은 단계 적용이라 초등 5~6학년은 **2026학년도부터** 적용된다. 지금이 첫 학기다. 실과의 정보 관련 시수는 17시간에서 **34시간 이상**으로 늘었다.

초등 5~6학년 실과 **'디지털 사회와 인공지능'** 영역의 성취기준은 다섯 개다.

| 코드 | 성취기준 | 놀AI |
|---|---|---|
| 6실05-01 | 컴퓨터를 활용한 생활 속 문제해결 사례를 탐색하고 일상생활 속 문제를 해결하기 위한 알고리즘을 다양한 방법으로 표현한다 | 다루지 않는다 |
| 6실05-02 | 컴퓨터에게 명령하는 방법을 체험하고, 주어진 문제를 해결하는 프로그램을 작성한다 | 다루지 않는다 |
| 6실05-03 | 실생활의 문제를 해결하는 프로그램을 협력하여 작성하고, 산출물을 타인과 공유한다 | 다루지 않는다 |
| 6실05-04 | 디지털 데이터와 아날로그 데이터의 특징을 이해하고, 인공지능에 활용할 수 있는 데이터의 유형이나 형태를 탐색한다 | **레슨 1** |
| 6실05-05 | 인공지능이 만들어지는 과정을 체험하고, 인공지능이 사회에 미치는 영향을 탐색한다 | **비어 있음** |

6실05-05 성취기준 해설: *"기계학습이 적용된 간단한 인공지능 도구의 체험을 통해 기계학습의 기본 원리를 이해하고 인공지능으로 인한 사회의 발전과 직업의 변화를 이해하여 인공지능이 사회에 미치는 영향을 탐색할 수 있어야 한다."*

### 결정 1 — 레슨 1은 이미 6실05-04다. 이름표만 붙인다

레슨 1의 name 스텝은 *"컴퓨터는 말을 숫자로 바꿔서 기억해"*라고 말한다. 이것이 곧 아날로그 데이터(말)와 디지털 데이터(숫자)의 관계이고 "인공지능에 활용할 수 있는 데이터의 형태"다. 우연이 아니라 개념이 같다. **콘텐츠를 고칠 것은 없고 매핑만 기록한다.**

레슨 2(벡터검색)에 대응하는 성취기준은 없다. 6실05-05에 걸 수는 있지만 억지다. **교육과정 밖 심화로 둔다.** 레슨 1→2가 하나의 이야기를 이루는 것이 이 서비스의 서사이므로 뺄 이유가 없다.

### 결정 2 — 6실05-01~03(프로그래밍)은 다루지 않는다

1장의 포지셔닝("엔트리 다음에 오는 곳") 그대로다. 알고리즘 표현과 프로그램 작성은 엔트리·스크래치가 이미 잘한다. 여기 들어가면 놀AI의 정의가 흐려진다. 13장 B의 "코딩 기본 개념 레슨 — 기술적 장벽 없음, 전략 문제일 뿐"과 같은 판단이다.

따라서 놀AI가 대응할 수 있는 성취기준은 **다섯 중 04와 05 둘뿐**이고, 그중 하나가 비어 있다.

### 결정 3 — 6실05-05에 들어간다. 단 기존 도구와 같은 방식으로 하지 않는다

여기에 정면 충돌이 있다. 1장은 분류·학습데이터 영역을 "포화됐다"며 의도적으로 피했는데, 6실05-05가 요구하는 "기계학습 체험"이 정확히 그 영역이다. **교육과정을 반영한다는 것은 피하기로 한 곳에 들어간다는 뜻이다.** 이 모순을 감추지 않는다.

들어가되 같은 것을 만들지 않는다. 기존 도구가 멈추는 지점이 분명하기 때문이다 — *"예시를 많이 주면 컴퓨터가 구분한다"*까지만 보여주고 **왜 구분되는지는 보여주지 않는다.** 놀AI에는 이미 진짜 좌표 지도가 있다. 아이가 예시를 몇 개 놓으면 지도 위에 경계가 그려지고, 예시를 바꾸면 경계가 따라 움직이는 것을 보여줄 수 있다. 이것은 포화 영역 재진입이 아니라 그 영역에서 아무도 하지 않은 부분이다.

### 결정 4 — 성취기준 코드는 아이에게 보이지 않는다

레슨 JSON에 필드 하나를 더한다. 13장이 말한 `lang`과 같은 급의 값싼 추가이며 뼈대를 바꾸지 않는다.

```json
"curriculum": { "subject": "실과", "grade": "초5~6", "code": "6실05-04" }
```

**이 값은 랜딩 페이지와 (나중의) 부모·교사 화면에만 노출한다.** 놀이터나 레슨 화면에 성취기준 코드가 뜨는 순간 놀이터가 학습지가 되고, 2장의 원칙 1(설명보다 조작이 먼저)·2(틀린 답이 없다)와 정면으로 부딪친다. *"학교에서 배우는 그거예요"*는 아이가 아니라 허락하는 사람에게 하는 말이다. 3장에서 SEO 대상을 랜딩 페이지로 한정한 것과 같은 자리다.

재사용한 것은 EmbeddingMap(비슷한 말끼리 모여라·말이 달라도 뜻이 같으면),

많을수록 또렷해)뿐이고 나머지는 레슨마다 새로 만들었다. **매번 만들기 전에 숫자로
재보는 것이 이 프로젝트의 실제 비용이다.**
